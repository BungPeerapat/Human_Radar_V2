# Task Workflow

ใช้ไฟล์ `task.md` หนึ่งไฟล์ต่อหนึ่งงาน เก็บในโฟลเดอร์ย่อยที่มีรหัสและชื่อสั้น ๆ แล้วย้ายทั้งโฟลเดอร์เมื่อเปลี่ยนสถานะ

```text
tasks/
  todo/
  doing/
    006-beep-reconnect-timing/task.md
    008-radar-menu-lock/task.md
  done/
    009-compact-lock-countdown/task.md
    007-update-server-fallback/task.md
    005-touch-lock-input-guard/task.md
    004-radar-fullscreen/task.md
    003-radar-touch-lock/task.md
    001-primary-mqtt/task.md
    002-ota-server-migration/task.md
```

## สถานะและวิธีทำงาน

- `todo/`: งานที่บันทึกแล้ว ยังไม่เริ่มดำเนินการ
- `doing/`: งานที่เริ่มทำแล้ว รวมถึงงานที่ติดปัญหา ให้ระบุปัญหาและขั้นตอนถัดไปในไฟล์
- `done/`: งานที่ผ่านเกณฑ์ตรวจรับครบ พร้อมหลักฐานการทดสอบ

เริ่มงานโดยย้าย เช่น `tasks/todo/001-primary-mqtt/` ไป `tasks/doing/001-primary-mqtt/` โดยคงรหัสและชื่อเดิม ห้ามมีงานรหัสเดียวกันอยู่หลายสถานะ ตำแหน่งโฟลเดอร์คือสถานะจริง ไม่ต้องเพิ่มช่องสถานะที่อาจขัดกันในไฟล์

## ข้อมูลที่ต้องมีใน task.md

ระบุเป้าหมาย ความสำคัญ ขอบเขต ขั้นตอนที่เป็น checklist เกณฑ์ตรวจรับ สิ่งที่ต้องพึ่งพา และบันทึกผล ใส่ผู้รับผิดชอบเมื่อเริ่มงาน พร้อมวันที่ commit ที่ทดสอบ คำสั่ง/ผลตรวจ และปัญหาคงค้างเมื่อมีข้อมูล

งานที่ยังต้องทดสอบกับ ESP32 จริงต้องอยู่ `doing/` จนกว่าจะมีผลทดสอบหรือผู้ใช้ตกลงเปลี่ยนขอบเขต ห้ามถือว่าการอ่านโค้ดหรือ build ผ่านเป็นหลักฐานว่า OTA ใช้งานจริงได้

## ลำดับงานรอบนี้

1. เริ่มตรวจเส้นทาง OTA ในงาน `002` ก่อนเปลี่ยนระบบจริง
2. ทำงาน `001` และทดสอบ MQTT ใหม่ในสภาพแวดล้อมทดสอบ
3. ตรวจ OTA ผ่าน MQTT ใหม่ตามงาน `002` ก่อนย้ายอุปกรณ์จริงทั้งหมด

การย้าย MQTT ต้องรักษาช่องทาง OTA ของอุปกรณ์เดิมไว้จนกว่าจะยืนยันว่าเชื่อมต่อ broker ใหม่ได้ อย่าฝังรหัสผ่านลงไฟล์งาน โค้ด หรือ Git ให้อ้างอิงตำแหน่ง secret ตาม `docs/REMOTE_DEVELOPMENT.md`

## การใช้งานบนเซิร์ฟเวอร์

โครงสร้างเดียวกันอยู่ที่ `/root/project/Human_Radar_V2/tasks/` หลังเริ่มพัฒนาบนเซิร์ฟเวอร์ ให้ใช้ชุดนั้นเป็นชุดทำงานหลัก และส่งการเปลี่ยนแปลงผ่าน Git เมื่อตั้งค่า GitHub authentication พร้อมแล้ว หลีกเลี่ยงแก้ไฟล์งานเดียวกันทั้ง Windows และเซิร์ฟเวอร์พร้อมกัน
